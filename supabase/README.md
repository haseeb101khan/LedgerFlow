# Supabase Setup

The production foundation is in `migrations/0001_platform_foundation.sql`.

## Apply Migration

After creating a Supabase project and installing the Supabase CLI:

```bash
supabase link --project-ref your-project-ref
supabase db push
```

Or run the SQL manually in the Supabase SQL editor during early development.

## Storage

Create a private bucket:

```text
organization-documents
```

Files should live in Supabase Storage. The database stores metadata in the `documents` table.

## Security Notes

- Keep `SUPABASE_SECRET_KEY` server-side only.
- Browser code should use the publishable key and rely on RLS.
- Every business table is organization-scoped.
- `organization_modules` controls which product areas are enabled for each tenant.
- `organization_roles.permissions` stores flat action keys such as `inventory.update`; RLS checks these with `app.has_permission`.
- `role_field_permissions` supports hidden, visible, and editable field overrides.
- Custom field definitions are configuration. Values live in record `custom_data` JSONB; migrations never add customer-specific columns.
- Audit logs are generated by triggers and should not be inserted directly by normal application users.

Do not connect customer data until the NestJS header-based organization placeholder has been replaced with verified Supabase JWT and membership resolution.
